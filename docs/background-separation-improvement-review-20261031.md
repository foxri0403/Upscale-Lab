# 배경 분리 품질·응답 속도 개선 판단

2026-10-31 현재 코드와 공식 모델 문서를 바탕으로 정리한 개선안이다. 이번에는 메뉴 중복을 수정했으며 아래 모델·추론 경로 변경은 구현하거나 운영에 적용하지 않았다. 아래의 기대 효과는 코드 구조에 따른 판단이며 실측 성능 향상률이 아니다.

## 현재 경로에서 확인한 제약

- 자동 분리는 `gpu-worker-runpod/layers/pipeline.py`의 BiRefNet_HR-matting과 big-lama를 사용한다. BiRefNet 입력은 2048×2048이며 알파를 원본 크기로 되돌린다. LaMa는 긴 변을 최대 2048로 줄여 채우고 원본 크기로 확대한다. 마스크 밖의 배경 픽셀은 원본을 보존한다.
- 수동 선택은 `web/src/smart-selection.worker.ts`의 SlimSAM, FP32, 단일 스레드 WebAssembly CPU를 사용한다. `SubjectSeparation.tsx`에서 마스크의 긴 변을 최대 1600으로 만든 뒤 내보낼 때 원본 크기로 확대한다.
- 수동 마스크가 있으면 서버 worker는 BiRefNet을 건너뛰고 전달받은 마스크를 그대로 전경 알파로 사용한다. 따라서 원래 자동 분리에 있던 세밀한 알파를 수동 재선택의 거친 경계가 대체할 수 있다. 단순 확대와 경계 흐림만으로 털이나 가는 머리카락을 복원할 수는 없다.
- 현재 양성 힌트는 주로 대표 내부점 하나다. 여러 지점에 걸친 피사체와 가는 꼬리·다리, 배경이 많이 섞인 선택에서 정보가 부족할 수 있다. 지우개도 음성 힌트로 전체 피사체를 다시 추론하므로 수정하지 않은 영역이 함께 줄어들 수 있다.
- 이미지 특징은 같은 worker 안에서 재사용한다. 다만 작업실의 도구 탭을 바꾸면 worker를 폐기하므로 재진입 시 초기화·특징 계산이 다시 필요하다. 혼합된 도구/모드 그룹마다 순차 추론하고 같은 이미지 픽셀을 다시 전달한다.
- Cloud 상태 조회의 429/5xx를 한 번만 받아도 현재 요청은 실패한다. 완료 마커와 원격 작업 ID가 이미 있으므로 동일 작업을 제한 시간 안에서 재조회하면 불필요한 재실행을 줄일 여지가 있다.

## 권장 순서

### 1. 수정 영역과 선택 힌트를 먼저 개선

브러쉬·올가미의 최종 영역에서 여러 양성·음성 힌트와 주변 여유를 둔 관심 영역을 만든다. 기존 마스크를 기준으로 변경한 부분을 보정하고, 수정 밖의 확실한 선택은 유지한다. 올가미의 거친 경계에 최종 피사체를 강제로 잘라 맞추지 않는다. 지우개는 지정한 범위를 우선 제거하고 주변 경계만 보정해 다른 부위가 함께 사라지는 것을 줄인다.

현재 사용 중인 선택 모델로도 비교할 수 있는 첫 단계다. 모델 교체 효과와 입력 힌트 개선 효과를 구분해 평가한다.

### 2. 원본 해상도의 알파 경계 보정 추가

선택 마스크를 확실한 피사체·확실한 배경·불확실한 경계로 나눈 trimap으로 만들고, 원본 RGB와 함께 matting 모델에 입력한다. 가는 털·머리카락과 반투명 경계를 다루는 목적이다. 후보로 [ViTMatte](https://github.com/hustvl/ViTMatte)의 이미지+trimap 경로를 평가한다. 기존 BiRefNet_HR-matting은 자동 분리 기준 결과로 유지한다.

4K 사진의 경계 주변을 충분한 문맥과 함께 잘라 처리하면 전체 사진을 일률적으로 축소하는 것보다 원본의 세부 정보를 활용하기 쉽다. 조각 경계의 연결과 메모리 사용량은 실측한다. 흰색·검은색 배경에 합성해 가장자리의 색 번짐도 함께 검사한다.

현재 수동 마스크와 출력 알파가 같다는 계약이 바뀌므로 입력 마스크와 최종 알파를 구분해 기록해야 한다. 최종 알파를 저장하고 편집 화면에도 되돌려 줘 미리보기와 저장된 레이어가 일치하도록 한다. 사용자가 지운 확실한 배경은 경계 보정으로 복구하지 않는다.

### 3. 응답 속도와 실패 복구 개선

worker 수명을 탭보다 길게 유지하되 메모리 제한을 둔다. 같은 이미지의 픽셀·특징을 한 번만 준비하고 최종 선택 힌트를 묶어 불필요한 순차 추론을 줄인다. 동일 이미지·마스크·모델 버전의 결과는 사용자 소유권 범위 안에서 재사용한다.

429/일시적 5xx는 같은 원격 작업 ID와 완료 마커로 제한적으로 재조회한다. 재조회 실패를 새 `/run` 제출로 즉시 바꾸지 않아 중복 처리와 대기를 줄인다. 배경 채움은 확정된 선택에만 실행하는 현재 버튼 흐름을 유지한다.

### 4. 선택 모델 교체는 같은 사진으로 비교 후 결정

SlimSAM과 [SAM 2.1](https://github.com/facebookresearch/sam2)의 점·박스·기존 마스크 기반 보정을 서버 GPU에서 비교하는 것을 권장한다. SAM 2는 이미지 특징을 준비한 뒤 프롬프트로 마스크를 반복 예측하는 API를 제공한다. [SAM 3](https://github.com/facebookresearch/sam3)도 대화형 분할을 지원하므로 비교 후보로 삼을 수 있다. 모델의 지원 입력과 실제 서비스의 정확도·지연 개선은 별도로 검증한다.

서버 모델은 브라우저 기기 성능 편차를 줄일 수 있지만 업로드·서버 기동 대기·GPU 비용이 추가된다. 모델 이름만으로 교체를 확정하지 않는다. 로컬 GPU runner를 도입하지 않는다.

## 배경 채움 자체의 품질

LaMa는 긴 변 2048에서 장면 전체를 채운다. 큰 사진에서 피사체 뒤의 질감이 흐려지는 경우에는 충분한 주변 문맥을 포함한 채움 영역 처리와 원본 해상도 복원을 비교한다. 동일 마스크 재적용은 캐시하고, 변경 부분만 처리할 때는 이전 채움 영역 밖으로 되돌아온 부분을 원본에서 복원해야 한다. 단순히 기존 배경 위에 새 채움 결과를 덮으면 잘못된 구멍이나 연결선이 남을 수 있다.

## 평가 기준

동물 털, 머리카락, 얇은 물체, 복잡한 배경, 낮은 대비를 포함한 동일 사진 묶음과 동일한 사용자 선택을 사용한다. 전체 선택 정확도, 경계 정확도·알파 오차, 검정/흰색 합성의 색 번짐, 재수정 횟수와 배경 채움의 연결 상태를 비교한다. 초기 실행과 반복 실행을 나눠 모델 준비·추론·업로드·대기·채움 시간의 중앙값과 상위 지연을 기록한다. 품질 향상과 GPU 처리량·비용을 함께 보고 운영 반영을 결정한다.

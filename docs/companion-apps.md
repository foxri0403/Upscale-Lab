# Windows / Android 연결 앱

웹의 **앱 다운로드**에서 Windows EXE와 Android APK를 받습니다. Windows와 Android만 표시합니다. 연결 앱에서 웹과 같은 계정으로 로그인하면 실제 화면 크기로 기기를 자동 등록하고 기기 자격을 발급받습니다. 웹의 **기기 관리** 또는 작업실에서 이미지와 화면을 선택하면 연결 앱이 내려받아 적용하고, OS에서 적용을 확인한 뒤 완료를 보고합니다.

## 사용 방법

1. 연결할 기기에 앱을 내려받아 실행합니다. Windows는 x64 Windows 10/11, Android는 7.0(API 24) 이상을 대상으로 합니다.
2. 서버 주소 입력 없이 웹과 같은 아이디/이메일 및 비밀번호로 로그인합니다. 서버는 빌드 시 앱에 포함됩니다. 비밀번호는 저장하지 않습니다.
3. 웹 기기 관리에 기기가 나타나면 화면별 배경화면을 선택합니다. 웹과 연결 앱은 인증된 변경 알림을 대기하다가 요청·처리 결과를 즉시 조회합니다. 20초 대기 응답은 변경이 없을 때의 연결 유지 시간입니다. Windows/Android 화면 연결·해상도 변경도 OS 이벤트로 즉시 보고하고, 30초 주기 보고는 보조로 유지합니다. 이미지 다운로드·OS 처리와 Android 최초 승인에 필요한 시간은 별도로 걸립니다. 이 동작은 **1.0.2 연결 앱으로 업데이트**해야 사용할 수 있습니다.
4. Android Live 2D의 첫 적용은 계정 팝업 설정의 **Live 2D 활성화**를 켜고 필요한 최초 시스템 확인 화면에서 적용합니다. 승인 전에는 웹에 **기기 확인 필요**로 표시됩니다. 시스템이 홈/잠금 화면을 함께 바꾸는 기종에서는 실제 변경 상태를 보고합니다.
5. 로그인 중 동기화는 항상 활성화하며 로그아웃하면 새 요청을 적용하지 않습니다. 적용된 정적 배경화면은 남고 Live 2D 움직임은 중지합니다. 로그아웃은 이 앱의 계정 세션을 폐기합니다.

Windows 창을 닫으면 트레이에서 계속 실행합니다. 트레이의 종료로 완전히 끌 수 있습니다. Windows 시작 시 실행은 사용자가 선택합니다. Android는 동기화 중 시스템이 요구하는 실행 알림을 표시합니다. 계정 팝업의 알람 스위치는 배경화면 적용 등 일반 알림을 제어하며 필수 실행 알림은 유지합니다. 자동 로그인을 켠 기기는 재부팅 후 연결을 복원합니다. Android 제조사의 백그라운드 제한이나 네트워크 상태에 따라 갱신이 지연될 수 있습니다.

## 수집 범위와 인증

1.6.0 운영 빌드는 Windows 설치 시, Android 첫 실행 시 기기·화면 정보 수집·이용 안내와 기본 미선택인 필수 동의를 표시한다. Windows 설치 없이 직접 실행하거나 기존 설치를 업데이트할 때도 동의가 없으면 동의 화면부터 표시한다. 안내에는 수집 목적·항목과 동의 거부 시 연결 앱을 사용할 수 없음을 명시한다. 안내 버전·UTC 동의 시각·서버를 로컬에 기록하며, 동의와 로그인 확인을 마친 뒤에만 화면 정보를 읽고 변경 이벤트를 구독한다. 로그인 전에는 로그인 기능만 표시하고 로그아웃 후에는 화면 정보를 비운다. Android 시스템의 APK 설치 화면은 앱에서 변경하지 않는다.

수집은 OS 디스플레이 API로 수행합니다. 기기 이름·모니터 이름, 연결된 물리 화면 개수, 픽셀 해상도, 소수점 주사율, 배율, 회전, 위치, 주 화면, 연결 상태와 OS 버전·연결 앱 버전을 보고합니다. 제조사·모델·CPU 구조는 수집하거나 표시하지 않습니다. Android의 홈/잠금은 한 물리 화면의 적용 대상이며 화면 개수에 중복 계산하지 않습니다. 화면을 꺼도 연결된 물리 화면으로 유지합니다. Android 외부 디스플레이는 공개 WallpaperManager API로 개별 적용할 수 없어 **정보 조회 전용**으로 보고하고 웹/API에서 적용을 차단합니다.

이 앱이 적용한 배경화면은 결과물 ID와 OS의 적용 식별자를 대조합니다. 다른 프로그램/사용자가 바꾼 배경화면은 External/Unavailable로 보고합니다. 외부 배경화면의 원본 사진, 로컬 경로, 다른 앱 목록, MAC 주소와 일련번호는 수집·전송하지 않습니다. Windows 모니터의 로컬 장치 경로는 안정적인 해시로 바꾸어 전송합니다.

모든 agent 요청은 유효한 계정 JWT와 해당 계정에 속한 기기 토큰을 함께 사용합니다. Windows는 현재 사용자 DPAPI, Android는 Android Keystore AES/GCM으로 기기 자격과 자동 로그인 세션을 보호합니다. 자동 로그인을 끄면 계정 세션은 메모리에만 유지합니다. 계정·서버별로 캐시와 적용 이력을 분리합니다. 웹에서 폐기한 기기 자격을 자동 재발급하지 않습니다. 사용자가 로그아웃 후 다시 로그인하면 계정 인증을 확인한 뒤 자격을 재발급합니다.

서명된 이미지 다운로드 URL에는 계정 JWT와 기기 키를 보내지 않습니다. 다운로드 캐시에는 만료 URL 대신 로컬 레이어 파일과 변환 정보를 저장합니다. 다운로드 후에도 최신 화면·요청 순서·결과물 ID를 다시 확인하고 대체된 명령은 적용하지 않습니다. 네트워크가 끊기면 재시도하며 실제 적용 후 보고 실패를 적용 실패로 바꾸지 않습니다.

## 구현 및 제한

- `companion/windows`: .NET 8 WinForms, 단일 EXE에 .NET 런타임 포함. 정적 배경은 IDesktopWallpaper, Live 2D는 Explorer WorkerW 아래 별도 렌더 창과 마우스 시차를 사용합니다. Explorer 구성에 따라 Live 2D 호스트를 찾지 못하면 지원하지 않는 것으로 보고합니다. Windows 잠금 화면은 지원하지 않습니다.
- `mobile/lib/companion.dart`: Flutter 연결 전용 화면. Kotlin foreground service가 네트워크·기기 자격·WallpaperManager를 처리하므로 Flutter 화면을 닫아도 동기화합니다. 기존 Kotlin Live 2D 엔진과 자이로 센서를 재사용하며 계정 인증의 유효 시간이 지나면 움직임을 중지합니다.
- 기본 앱 진입점은 연결 화면입니다. 실행되지 않던 옛 모바일 편집/보관함 화면과 전용 네이티브 채널은 정리했으며 현재 배경화면 엔진·센서·companion 캐시는 유지합니다. 이미지 처리는 웹/API의 클라우드 규격을 사용합니다.
- Windows EXE는 현재 Authenticode 코드 서명 인증서가 없어 서명되지 않았습니다. Android APK는 팀 공유 릴리스 키로 서명합니다. 다른 인증서로 배포한 예전 APK와의 덮어쓰기 설치는 별도 인증서 확인이 필요합니다.
- Windows 실제 화면 정보 수집은 확인했습니다. 실제 기기의 계정 로그인 → 웹 적용 → OS 배경화면 변경과 Android 제조사별 홈/잠금 동작은 설치 후 통합 검증이 필요합니다. 실제 OS 적용과 Android 에뮬레이터 통합 검증은 설치 후 별도로 확인합니다.

## 빌드와 다운로드 배포

APK 버전/빌드 번호는 `AGENTS.md`, `mobile/pubspec.yaml`, `mobile/README.md`를 함께 갱신합니다. 공유 서명 설정은 Git 밖 파일을 지정하고 `apksigner verify --print-certs`로 반드시 검증합니다. 최신 운영 APK는 **1.6.0+45**, Windows 앱은 **1.6.0**입니다. 임의 로그인과 테스트 표시를 제거하고 실제 계정 인증을 사용하는 버전으로 배포합니다. 앱 아이콘·모바일/PC UI·서버 입력 제거·태블릿 미리보기·바탕화면 바로 가기 설치를 추가했으며 기기 이름·OS·화면 해상도·주사율은 유지합니다. 신규 Android 기기는 OS에 설정된 이름으로 등록하며 이름을 읽을 수 없을 때만 일반 이름을 사용합니다.

Windows Live 2D는 아이콘 아래·시스템 배경 위의 layered child 창을 사용하며 테마 변경 후 순서를 재확인한다. Android는 gyroEnabled와 센서 지원에 따라 회전 벡터 또는 원시 자이로를 사용한다. 배경화면 삭제는 선택 화면의 OS 초기화를 확인한 뒤 보고하며 다른 화면과 개인 보관함은 보존한다. 실기기별 동작은 별도 확인한다.

```powershell
$env:UPSCALE_SIGNING_PROPERTIES_FILE = 'C:\UpscaleLab-Secrets\key.properties'
.\companion\Build-Release.ps1 -ApiBaseUrl 'https://YOUR_SERVER' -Flutter 'C:\dev\flutter\bin\flutter.bat'
```

빌드 스크립트는 HTTP 테스트 서버를 명시한 경우에만 `COMPANION_ALLOW_HTTP=true`를 빌드 인수로 전달합니다. 기본 릴리스 설정은 HTTP를 허용하지 않습니다. 서버 주소는 빌드 인수로 공급하며 코드에 운영 환경별 값을 추가하지 않습니다. `-LocalTest`는 별도 테스트 패키지·설치 경로를 사용하고 운영 다운로드 파일을 교체하지 않습니다.

스크립트는 서명을 검증한 APK와 Windows EXE를 무시되는 `web/public/downloads/`에 복사하고 버전·SHA-256·바이트 크기·동일 출처 다운로드 URL을 `manifest.json`에 기록합니다. 그 후 `web`에서 `pnpm run build:cloud`를 실행하고 정적 파일 전체를 수동 배포합니다. 바이너리/서명키는 Git에 커밋하지 않습니다. `/downloads/`는 SPA fallback 없이 파일 부재 시 404를 반환해야 하며 manifest는 캐시하지 않습니다.

`build:cloud`는 빌드 전후에 Windows·Android 설치 파일의 존재, 버전, 크기와 SHA-256을 검사합니다. 기존 1.2.2 배포본을 재사용할 때는 검증된 `downloads/` 전체를 `web/public/downloads/`에 준비해야 합니다. 수동 웹 설치 도구 `deploy/install-web.sh`는 다운로드 디렉터리가 없는 이전 형식의 웹 묶음을 설치할 때 기존 릴리스의 다운로드 디렉터리를 보존하며, manifest와 EXE·APK가 없으면 전환을 중단합니다. 이 복구로 새 APK를 생성하거나 앱 버전을 올리지 않습니다.

## 백엔드와 DB

`20261027034626_AddCompanionInventory`가 추가했던 devices의 Manufacturer/Model/Architecture 열은 스키마 호환을 위해 남아 있지만 신규 값을 저장하지 않습니다. 기존 값은 다음 유효 heartbeat에서 비우며 구형 앱의 해당 필드는 무시합니다. device_displays의 RefreshRateHz/CanApplyWallpaper는 유지합니다. 주사율 미보고는 null이며 기존 화면의 적용 가능 기본값은 true입니다. 잘못된 주사율·기기 정보는 상태 변경 전에 검증합니다. 정보 조회 전용 화면은 적용 요청을 거부합니다.

기기 관리의 최근 적용 내역, 웹 기록 저장·조회 코드와 계정용 내역 조회 API는 제거했습니다. 기기 명령 저장은 전달·재시도·중복 요청 방지·현재 적용 결과물 복구에 사용합니다. 웹은 기기 state의 실제 배경화면·대기 상태만 조회합니다.

`backend/tools/UpscaleLab.DatabaseTool`은 운영자가 명시적으로 실행하는 유지보수 도구입니다. `status`로 대상 DB/소유자와 미적용 migration을 확인하고, `apply-companion /absolute/backup.dump`는 새 migration 하나만 남아 있을 때 `pg_dump` 전체 백업을 완료한 뒤 적용합니다. DB 자격은 서비스와 같은 보안 환경 공급자로만 받으며 명령행 인수나 로그에 출력하지 않습니다. API 시작 시 자동 migration이나 자동 배포를 추가하지 않습니다.

관련 규격: [agent API](agent-api.md). 플랫폼 문서: [Windows IDesktopWallpaper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idesktopwallpaper), [Android Display.Mode](https://developer.android.com/reference/android/view/Display.Mode), [Android specialUse foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types#special-use).

최신 로컬 정리 검증은 [정리 보고서](repository-cleanup.md)를 참고합니다. 실제 기기의 OS 배경화면 적용·삭제와 제조사별 동작은 설치 후 통합 확인이 필요합니다. 운영 배포에서는 HTTPS 서버 주소가 포함된 Windows EXE와 공유 키로 서명한 Android APK를 함께 갱신합니다. 로컬 테스트 패키지는 운영 다운로드에 포함하지 않습니다.

## 로컬 테스트와 연결 키

[EXE/APK 로컬 테스트 가이드](../companion/LOCAL-TESTING.md)에 API·웹·에뮬레이터 실행 절차를 정리했다. 테스트 빌드는 별도 설치 경로/패키지를 사용한다. Windows는 바탕화면·시작 메뉴 바로 가기를 선택해 사용자별로 설치하며 EXE의 `--run`으로 설치 없이 직접 실행할 수 있다. 기존 로고는 `web/public/favicon.svg`에서 변환한 아이콘을 사용하며 `companion/Update-BrandAssets.ps1`로 동기화한다.

웹은 내장 Android 화면의 짧은 변을 배율로 나눈 값이 600dp 이상이면 태블릿으로 표시한다. 기존 모니터·모바일과 같은 카드·메타데이터·홈/잠금 화면·버튼 구성을 유지하며 태블릿 테두리만 구분한다. 배율이 없는 구형 상태는 휴대폰으로 표시하고 외부 모니터로 태블릿 여부를 판별하지 않는다. 새 DB 필드나 마이그레이션은 필요하지 않다.

계정 JWT는 사용자 세션, 기기 키는 해당 계정의 특정 기기를 인증한다. 앱 로그인 시 자동 발급하므로 웹의 수동 키 재발급 메뉴는 제거했다. 기존 키가 폐기되거나 기기 등록이 삭제된 경우 앱에서 로그아웃 후 다시 로그인한다. 내부 발급·검증 API는 유지하며 키만으로 계정 인증을 대체하지 않는다.

## 1.6.0 연결 앱 구성

Windows는 로고 없는 큰 제목과 우측 상단의 원형 프로필 사진·아이디·이메일·플랜을 표시한다. 기기 제목·녹색/주황색/빨간색 연결 상태·화면 로그를 한 박스에 모으고, 주 화면 표시는 해상도·주사율 뒤에 붙인다. 수집 정보 안내와 로그아웃은 우측 하단에 배치한다. 아이디 저장과 자동 로그인은 같은 행의 좌측에 각각 표시한다. 아이디는 계정 세션과 별도의 서버별 DPAPI 파일에 저장하며 비밀번호는 저장하지 않는다. 바로가기는 현재 사용자·서버 범위의 named pipe로 기존 창을 복원한다.

모바일은 기기 요약과 동기화 스위치를 제거하고 헤더 바로 아래에 연결된 화면을 표시한다. 잠금 화면·홈 화면 순서이며 화면 아이콘은 단순한 선 형태를 유지한다. 계정 팝업은 이름·이메일·플랜을 조회하고, 알람·Live 2D 설정과 로그아웃을 제공한다. 아이디 저장은 Android Keystore로 보호하는 기존 저장소를 사용하고 자동 로그인 여부와 분리한다. 프로필·플랜 조회는 기존 인증 API를 사용하며 조회 실패 시 임의의 플랜을 표시하지 않는다.

Live 2D는 설정에서 켜면 앱 사용 의사를 기록한다. 대기 중인 결과물이 준비되면 필요한 Android 시스템 적용 화면을 열며, 취소하면 꺼짐으로 되돌린다. 별도 승인 카드는 표시하지 않는다. 시스템 및 엔진의 실제 적용을 확인한 뒤에만 Applied를 보고하고, 설정을 끄거나 계정 세션이 만료되면 움직임을 중지한다. 알람은 배경화면 적용 등 일반 이벤트를 제어하며 Android의 필수 백그라운드 실행 알림과 구분한다.

# 작업실의 AI 피사체 선택

기존 작업실의 도구 탭, 캔버스, 설정 패널과 색상 체계를 유지한다. 배경 분리 탭에 들어가면 원본을 표시한다. 탭 진입, 브러쉬·지우개·올가미, 실행 취소·다시 실행으로 AI 인식이나 레이어 갱신을 시작하지 않는다.

위의 **배경·피사체 분리 시작**으로 최초 자동 분리를 실행해 전경·배경 레이어와 선택 영역을 표시한다. 이후 브러쉬·올가미로 대략 지정한 영역을 테두리와 내부 색칠로 먼저 표시한다. 도구로 그린 미인식 영역이 있으면 시작 버튼을 잠그고, 아래의 **선택한 영역으로 피사체 적용**으로 현재 힌트를 재인식한다. 아래 버튼은 선택을 비우지 않고 선택 경계만 갱신하며 서버 레이어를 변경하지 않는다. 올가미는 드래그하거나 꼭짓점을 클릭하고 첫 점/Enter로 닫는다. 지우개는 선택을 즉시 빼며, 재인식 시 음성 힌트와 제거 범위를 함께 적용해 지운 곳을 다시 칠하지 않는다. 브러쉬의 우클릭 지우기와 별도의 피사체 선택·제외할 영역 버튼은 제공하지 않는다. 선택 초기화는 작업 중 선택을 되돌린다.

인식 결과를 확인한 뒤 위의 **배경·피사체 분리 시작**을 눌렀을 때만 원본 크기 마스크를 제출하고 실제 전경·배경을 갱신한다. 인식 후에는 시작 버튼을 다시 사용할 수 있고, 다시 그리면 재인식 전까지 잠근다. 자동 갱신 설정은 제공하지 않는다. 적용 후에도 선택과 이력을 유지한다. 실패 시 선택을 보존하며 공개 잠금과 중복 제출 방지를 유지한다. 아래 버튼은 이전 수정 사항 적용 버튼과 같은 글꼴·크기·굵기에 흰 배경과 파란 글자를 사용한다. 별도의 피사체 다시 분리·수정 사항 적용 버튼은 제공하지 않는다.

그리는 동안에는 native Canvas 경로로 새 획만 누적한다. 커서 이동은 React 전체 작업실을 다시 렌더링하지 않는다. 테두리·색칠 계산은 프레임당 한 번, 화면 크기에 맞춘 최대 긴 변 960px에서 수행한다. 인식 캔버스는 기존 최대 1600px, 내보내기는 원본 해상도를 유지한다. 이력 재생은 실행 취소·초기화 등에만 수행한다.

## 처리 경로

1. 힌트 없는 최초 분리 시작은 편집 중인 소유 프로젝트의 기존 RunPod BiRefNet/LaMa 경로를 실행한다. 완료한 전경 알파를 선택 영역으로 표시하며 미적용 수정으로 취급하지 않는다. 탭 재진입은 원본부터 보여주고 처리를 자동 실행하지 않는다. 클라우드 중간 파일의 보관·만료 설정 절차는 [클라우드 처리 문서](cloud-processing.md)를 따른다. 기존 마스크가 있으면 초기 힌트로 재사용한다.
2. Web Worker의 [SlimSAM](https://huggingface.co/Xenova/slimsam-77-uniform) (Apache 2.0, revision `5850ab45f587c112167512ffef949107115e26a0`)과 Transformers.js 3.8.1이 대략적인 선택을 실제 피사체 마스크로 바꾼다. WebAssembly CPU에서 실행하며 이미지당 특징을 재사용한다. 초기 마스크 내부의 양성 힌트, 배경·제거 영역의 음성 힌트, 후보 검증과 연결 영역 제거로 배경의 불필요한 섬을 줄인다.
3. `POST /api/projects/{id}/subject-mask`로 흑백 PNG와 현재 피사체 레이어 ID를 보낸다. API는 소유권, 계정 세션, 공개 잠금, 진행 중 작업, 오래된 레이어 ID, 이미지 크기·마스크 범위를 검증한다.
4. 기존 RunPod layers v1.2.0이 마스크를 전경 알파에 적용하고 LaMa로 피사체 뒤 배경을 채운다. 전경·배경은 원본 해상도로 저장한다. 초기 자동 분리와 배경 채움은 기존 클라우드 처리 경로를 사용한다.

모델은 처음 사용할 때 내려받아 브라우저에 캐시한다. 사용자 이미지를 Hugging Face에 보내지 않는다. 모델 다운로드에 실패하면 상태와 오류를 표시하며 선택 영역을 임의로 확정하지 않는다. 털·투명체·겹친 물체와 낮은 대비에서는 재선택이 필요할 수 있다. 브러쉬의 픽셀 처리와 기존 수동 올가미 구현의 출처는 [PhotoCraft MIT 고지](../third_party/photocraft/README.md)를 참고한다.

## 운영 반영

API에는 nullable `processing_jobs.SubjectMaskObjectKey` 컬럼이 필요하다. 해당 컬럼과 migration이 이미 존재하는 서버에서는 DB 변경 없이 배포한다. 기존 worker의 마스크 입력 지원을 확인한 경우 GPU 이미지나 endpoint를 변경하지 않는다.

실험실 `/lab/separation`과 별도 InMemory API는 개발 모드에서만 제공한다. 운영 빌드에는 작업실에서 사용하는 선택 Worker와 WASM을 포함하고 실험실 화면은 포함하지 않는다. 운영 API에 실험실 세션이나 임시 인증 경로를 추가하지 않는다.

검증: TypeScript 검사, 웹 동작 단위 테스트, backend xUnit, worker 입력/출력 테스트 및 실제 클라우드 마스크/레이어의 픽셀 비교. 로컬 실험실 절차는 [SeparationLab README](../backend/tools/UpscaleLab.SeparationLab/README.md)를 참고한다.

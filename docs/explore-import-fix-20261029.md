# 탐색 이미지의 내 이미지 저장 오류 수정

## 원인과 수정

모바일 갤러리 게시물의 웹 저장은 S3 미리보기 URL을 발급받아 브라우저에서 원본을 내려받은 뒤 다시 업로드했다. 운영 공개 게시물 원본의 실제 GET 요청은 PNG로 정상 응답했으나 웹 origin에 대한 `Access-Control-Allow-Origin` 헤더가 없어 브라우저의 fetch가 CORS 정책에 의해 차단됐다. 이미지 표시만 가능한 상태라 목록 조회·일반 화면 점검으로는 이 오류를 발견하지 못했다.

인증된 `POST /api/gallery/{id}/import`를 추가했다. 서비스가 게시물의 공개 여부 또는 작성자 소유권을 검증한 뒤 저장소 키로 원본을 읽고 기존 프로젝트 생성 서비스를 호출한다. 원본 검증·형식 정규화·S3 업로드·실패 시 정리는 기존 경로를 재사용하며, 가져온 이미지는 요청 계정 소유의 독립된 비공개 보관함 프로젝트가 된다. 타인의 원본 프로젝트 ID나 스토리지 경로를 내 소유 리소스로 재사용하지 않는다. 갤러리의 다운로드 횟수는 증가시키지 않는다.

웹은 동일 origin의 가져오기 API 한 번을 호출하고 보관함을 갱신한다. S3 공개 범위·CORS·버킷 정책을 변경하지 않는다. 기존 웹 배경화면 가져오기 API와 모바일/태블릿 레이아웃은 유지한다. DB migration·GPU 처리·연결 앱 업데이트는 필요 없다.

## 검증

- 백엔드 전체 xUnit 208건 통과. 새 회귀 테스트는 실제 프로젝트 생성/이미지 정규화를 포함한 소유권 분리, 비공개/없는 게시물 차단, 저장소 읽기/업로드 실패 및 재시도를 검증한다.
- 웹 빌드와 로컬 동작 테스트 53건 통과. 새 운영 점검은 갤러리 가져오기 라우트가 로그인 없이 401을 반환하는지 확인한다.
- 운영 API 검토 소스 206개 파일을 줄바꿈을 정규화해 비교했다. 이번 수정 외의 기존 API 코드 변경은 없다.

## 수동 배포

- 브랜치: `gusrb03/mobile-tablet-ui`, 배포 코드: `853762ef5b75372adeb36f522d2f3151742f0834`.
- 릴리스: `gallery-import-20261029-151441` (2026-10-29 15:14 KST). 원격 푸시 후 해당 커밋을 Git archive로 추출해 Linux API 및 cloud 웹을 빌드했다.
- [운영 웹](https://d3bjir1z2hduu0.cloudfront.net/)의 API와 웹을 순서대로 수동 전환했다. 기존 런타임 의존성 32개 파일의 해시가 동일함을 확인하고 API 자체 DLL/PDB만 교체했다.
- 운영 HTTPS에서 임시 계정으로 실제 다른 사용자의 공개 게시물을 가져왔다. 내 보관함 조회, 사본 이미지 읽기, 소유권 분리, 타 계정·비공개·없는 게시물 접근 차단을 확인했다. 작성자의 원본·공개 상태·다운로드 횟수는 유지됐다.
- 검증 계정 두 개와 사본·비공개 검증 게시물은 기존 계정 정리 서비스를 통해 제거했다. 실제 사용자 계정·원본 이미지·기기 상태는 변경하지 않았다.
- 배포 후 웹 테스트 및 운영 HTTPS 점검 68건 전체 통과. `/health`, API 서비스와 nginx 활성 상태, CloudFront의 새 번들 반영도 확인했다.
- 이전 API `studio-crop-20261029-105304`와 웹 `mobile-tablet-20261029-042149`, 복구 포인터·검증 기록을 보존했다. 이번 업로드·staging·배포 도구는 제거했다.

이 결과 기록은 코드 배포 후 문서만 갱신한 별도 커밋으로 보존한다. 배포 전에 열어 둔 웹 화면에서는 새로고침 후 변경된 가져오기 경로를 사용한다.

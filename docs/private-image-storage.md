# 앱 전용 이미지 저장소

새로 등록하거나 탐색에서 저장한 이미지는 `files/image_library/<사용자 해시>/<이미지 ID>/source.<확장자>`에 보관합니다. `item.json`에 제목, 태그, 비율, UTC 시각, 공유 연결과 `mode=live2d`를 기록합니다. 선택한 원본 바이트를 그대로 복사하고 메타데이터는 별도 파일로 저장합니다. 픽셀을 편집한 경우에는 편집 결과를 복사합니다. MediaStore 등록이나 미디어 스캔을 호출하지 않으므로 새 저장본은 기기 갤러리에 나타나지 않습니다.

일반 저장·목록·수정·삭제에는 사진/저장소 권한이 필요하지 않습니다. 기기 사진 선택은 기존 시스템 선택기를 사용합니다. 캐시 정리, 로그아웃, 앱/기기 재시작 후에도 파일이 유지되며, 같은 사용자로 다시 로그인하면 보관함을 읽습니다. 다른 계정은 접근할 수 없습니다. 앱 데이터 삭제/제거 시 전용 파일도 제거되므로 이전 공용 앨범 방식의 재설치 자동 복원은 제공하지 않습니다. 선택한 원본 사진은 덮어쓰거나 삭제하지 않습니다. 별도의 명시적 사진 앨범 내보내기는 기존 동작을 유지합니다.

## 기존 버전에서 이전

이미 사진 읽기 권한이 있는 기존 설치는 보관함을 열 때 현재 계정의 `Pictures/Upscale Lab` 복사본을 한 번 이전합니다. 권한이 없거나 갤러리 복사본 삭제에 Android 확인이 필요한 경우 **설정 → 기존 갤러리 이미지 이전**을 사용합니다. 새 이미지 저장을 위해 전체 사진 접근을 요구하지 않습니다.

이전 대상은 지정된 앨범 안에서 `UpscaleLab_<이미지 ID>.<확장자>` 이름과 기존 사용자 메타데이터가 모두 일치하는 현재 계정의 파일입니다. 인물/배경 레이어 연결을 유지할 수 있도록 이미지 ID, 공유 정보, 비율과 Live 2D 모드를 보존합니다. 더 오래된 앱 전용 보관함 기록도 해당 서버/계정 소유권을 확인해 읽습니다. 공용 앨범으로 이전된 오래된 비공개 기록은 최신 앨범 메타데이터를 덮어쓰지 않습니다.

내부 이미지·메타데이터를 동기 기록하고 원본과 SHA-256이 일치하는지 확인한 뒤에만 공용 복사본을 삭제합니다. 복사 실패, 다른 계정, 앱에서 만든 이름이 아닌 사진, 충돌하는 픽셀은 삭제하지 않습니다. Android가 삭제 확인을 요구하면 확인 후 마무리합니다. 확인을 취소해도 내부 복사본은 보관하며, 남은 항목 수를 표시합니다. Android 10에서는 사진별 삭제 승인이 필요할 수 있으며, 남은 항목은 이전을 다시 실행해 승인합니다. 권한을 얻지 못하면 기기 갤러리에서 이전 완료한 복사본을 직접 지울 수 있습니다.

이미 저장된 내부 파일은 재이전으로 덮어쓰지 않습니다. 내부 원본 삭제는 다른 계정·선택한 기기 원본·공유 게시물에 영향을 주지 않습니다. 적용한 라이브 배경화면은 보관함과 분리된 영구 복사본을 사용합니다.

## 검증

`PrivateImageStoreTest`는 원본 바이트/확장자 보존, 캐시 원본 제거 후 다시 읽기, 계정 격리, 메타데이터 교체 중단 복구, UTC 변경 시각, 앱 복사본만 삭제, 이전 검증 순서와 삭제 거절/실패 시 데이터 보존을 검사합니다. Android 실기기에서는 새 등록본이 갤러리에 생기지 않는지, 기존 보관함이 이전 후 유지되는지, 선택한 원본은 그대로인지, 갤러리 삭제 확인 취소/허용과 앱 재시작을 확인하세요.

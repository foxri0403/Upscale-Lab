# 자동 분리 후 피사체 수정

> 이 문서는 기존 `/subject-mask` 직접 마스크 호환 계약과 당시 UI 기록이다. 현재 작업실은 [BiRefNet 선택 범위 보완](subject-selection-additive.md)을 사용하며 [2026-10-31 배포 기록](birefnet-roi-deployment-20261031.md)을 따른다.

2026-10-29 운영 반영을 완료했다. 릴리스·DB 백업·실제 GPU 검증은 [운영 배포 기록](subject-mask-deployment-20261029.md)을 참고한다.

웹 작업실의 **배경 분리 → 피사체 자동 분리**는 기존 BiRefNet_HR-matting + LaMa 작업을 실행한다. 완료하면 피사체의 투명 배경 미리보기를 먼저 보여 준다. **피사체 직접 수정**에서 복원/지우기 브러시, 크기 조절, 확대(100~400%), 화면 이동, 실행 취소/다시 실행, 수정 전으로, 원본 비교와 선택 영역 확인을 사용할 수 있다. 마우스·펜·터치를 지원한다. 닫기/취소 시 미적용 수정이 있으면 확인한다. 편집용 미리보기는 긴 변 1600px로 제한하고, 적용할 때 원래 전경의 알파에 원본 좌표의 브러시 작업을 다시 그려 원본 해상도를 보존한다.

수정 적용은 전체 캔버스의 불투명 흑백 PNG를 `POST /api/projects/{projectId}/subject-mask`에 multipart `mask`, `baseLayerId`로 보낸다. 흰색은 피사체, 검은색은 배경이며 회색은 가장자리의 알파다. `baseLayerId`는 편집을 시작한 전경 레이어 ID다. 서버는 소유권, 공유 잠금, 진행 중 작업, 최신 레이어, PNG 실제 형식/크기/투명도, 선택 영역을 검사한다. 50MB/64MP 제한을 적용하며 전체의 0.1% 초과, 98% 미만인 피사체가 필요하다. 202 응답 후 기존 processing-status를 조회한다.

수정 마스크는 사용자별 S3 `users/{userId}/projects/{projectId}/masks/{jobId}.png`에 보관한다. DB의 `ProcessingJob.SubjectMaskObjectKey`에는 경로만 저장하며 재시작 복구에도 같은 마스크를 사용한다. 원본 또는 마지막 성공한 업스케일 이미지에서 전경을 만들고, 수정한 마스크로 LaMa 배경 채우기를 다시 실행한다. 자동 추론으로 수정 영역을 덮어쓰지 않는다. 실패한 작업은 이전 레이어와 기존 업스케일 이미지를 유지한다. 완료한 새 레이어는 기존 저장·다운로드·결과물·기기 적용 경로에 그대로 연결된다. 프로젝트 폐기/삭제, 효과 초기화, 계정 삭제 시 마스크도 정리한다.

워커 요청에는 선택적 `mask_url`, `mask_sha256`가 추가된다. 기존 자동 요청은 그대로 지원한다. 워커가 완료 marker에 `maskSha256`를 돌려주어야 API가 수정 결과를 채택한다. 구 버전 워커가 마스크를 무시하고 자동 분리를 실행한 결과는 저장하지 않는다. 원격 재시작 복구도 이미지와 마스크 hash를 모두 대조한다.

## 수동 배포

이 변경은 운영 서버나 RunPod endpoint를 자동 변경하지 않는다.

1. `gpu-worker-runpod/layers` 이미지의 pipeline/handler를 새 버전으로 빌드하고 기존 분리 endpoint를 수동 갱신한다. 모델과 CUDA 요구사항은 기존과 같다.
2. `AddSubjectMaskRefinement` migration을 리뷰 후 수동 적용한다. `processing_jobs`에 nullable `SubjectMaskObjectKey`만 추가한다.
3. API와 웹을 함께 배포한다. 기존 `RunPod:LayersEndpointId`, S3 설정을 사용하며 새 비밀값은 필요 없다.
4. 실제 이미지에서 자동 분리 → 복원/지우기 → 처리 완료 → 새로고침/다운로드/기기 적용을 확인한다. 로컬 테스트는 저장소·클라우드 응답을 대체하며 실제 GPU 품질이나 실기기 적용을 보장하지 않는다.

## 로컬 검증 (2026-10-29)

- .NET 빌드 및 백엔드 218건, 웹 TypeScript/프로덕션 빌드 및 테스트 54건 통과. 운영 주소를 지정하지 않은 웹 smoke 15건은 건너뛰었다.
- 워커 계약 테스트 10건 통과. 수정 마스크 전달, 체크섬 확인, 기존 자동 요청, 임의 URL 거부, 가장자리 알파 보존을 검증했다.
- 브라우저 API 모의 응답으로 자동 결과 표시 → 브러시 복원/지우기 → 실행 취소/다시 실행 → 확대/화면 이동 → 터치/입력 취소 → 저장 오류 후 재시도 → 새 결과 조회 → 미적용 변경 취소를 확인했다. 1440/1000/768/390/320px에서 화면 넘침과 런타임 오류가 없었다.
- 400×300 및 2000×1500 PNG를 직접 디코딩하여 원본 해상도, 복원 255/지우기 0/미수정 가장자리 128의 흑백 값과 불투명 마스크 저장을 확인했다. EF 모델과 migration이 일치하며 SQL은 nullable 컬럼 하나만 추가한다.

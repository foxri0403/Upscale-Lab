# 자동 분리 후 BiRefNet 선택 범위 보완

1. **피사체 자동 분리**로 BiRefNet_HR-matting 전경과 LaMa 배경을 만든다. 결과가 없으면 브러쉬·지우개·올가미를 잠근다.
2. 결과가 준비되면 같은 버튼의 이름이 **피사체 다시 분리**로 바뀐다. 브러쉬·올가미는 보완할 범위를 표시하고 지우개는 제거할 범위를 표시한다. 획을 그리는 것만으로 추론하거나 칠한 배경을 전경으로 확정하지 않는다.
   올가미는 사용자가 그린 경로 그대로 닫아 표시한다. 이미지 경계에 맞추는 브라우저 추적은 실행하지 않는다. 브러쉬·올가미 확정 시 기존 획 전체를 재처리하지 않으며 실행 취소·다시 실행에만 이력을 재생한다. 선택 영역 보완 아래 설명 문단은 표시하지 않는다.
3. **피사체 다시 분리**를 누르면 표시 범위의 RGB 원본을 주변 문맥과 함께 잘라 같은 BiRefNet_HR-matting으로 추론한다. 예측과 추가 범위의 교집합만 기존 알파에 더하고 지우개 범위는 뺀다. LaMa로 최종 전경 뒤의 배경을 다시 채운다. 별도의 추가 영역 적용 버튼은 없다.

브라우저 SlimSAM은 운영 작업실에서 사용하지 않는다. 개발용 실험실의 기존 경로는 유지한다. 실행 취소·다시 실행·선택 초기화는 요청 전 범위 표시를 편집한다. 닫지 않은 올가미, 그리는 중, 처리 중에는 분리를 막는다. 표시한 수정이 없는 재분리 버튼은 잠근다. 실패하면 기존 레이어와 표시 범위를 보존한다.

## 데이터와 알파 보존

`POST /api/projects/{id}/subject-selection`은 `baseLayerId`와 원본 해상도의 불투명 PNG를 받는다. 클라이언트 PNG의 R은 추가 범위, G는 제거 범위, B는 0이다. API가 소유권·공개 잠금·현재 레이어·동시 작업·크기를 확인한 다음 서버에 저장된 현재 전경 알파를 읽는다.

워커에 보관하는 RGB PNG는 **R=서버의 기존 알파, G=추가 범위, B=제거 범위**다. 기존 작업 레코드의 마스크 key를 `.selection.png`로 구분하므로 큐 복구에도 모드가 유지된다. 추가 DB 컬럼이나 migration은 필요하지 않다. 기존 마스크 삭제·계정 정리 경로를 그대로 사용한다.

RunPod 입력의 `mask_mode=selection`은 ROI BiRefNet 경로를 선택한다. 완료 결과도 `maskMode=selection`을 반환해야 API가 받아들이므로 기존 워커가 범위를 단순 알파로 적용하는 잘못된 성공을 막는다. 기존 `/subject-mask`의 흑백 알파 직접 적용 계약도 호환한다.

원본 크기에서 추가 알파는 `max(기존 알파, ROI 매팅 알파 × 추가 범위)`이고 제거 범위를 마지막에 적용한다. 범위 밖 알파는 축소·확대하거나 다시 추정하지 않는다. 지우개만 있으면 BiRefNet을 재실행하지 않고 선택만 제거한다. LaMa의 배경 채움은 최종 알파를 사용한다.

## 검증

워커 검사는 ROI 입력, 칠한 배경 제외, 부드러운 알파, 범위 밖 픽셀 보존, 제거 범위와 완료 모드 확인을 검사한다. xUnit은 서버의 원본 알파 사용, 큐 복구, 소유권·오래된 결과·공개·동시 작업 차단, 이전 워커 거부를 확인한다. 실제 GPU 품질과 브라우저 동작은 별도로 검증한다.

`web/tests/cloud-selection.html`은 실제 편집 훅과 Canvas PNG를 사용해 3200×2000 원본에서 올가미 경로, 추가·제거 채널, 실행 취소·다시 실행과 50회 반복 브러쉬를 검사한다. 선택 PNG는 하나의 원본 크기 RGB 캔버스에 직접 그린다. 비어 있는 선택 검사는 256×256 타일로 읽어 전체 이미지 RGBA 복사본을 만들지 않는다. `web/tests/devices.html`은 오프라인 PC·휴대폰의 연결 문구와 모니터 이름·주 화면 배치를 검증하는 브라우저용 샘플이다.

# Upscale Lab Web

휴대폰·태블릿에서는 1100px 이하에서 접이식 메뉴와 세로 작업실을 사용합니다. 메뉴는 이동·바깥 선택·Esc로 닫히며 데스크톱 메뉴 설정과 분리됩니다. 600px 이하에서는 편집 도구 여섯 개를 3열·2행으로 모두 표시합니다. 미리보기 아래에 설정·저장·내보내기를 배치하고 페이지 스크롤로 접근하므로 화면 높이가 작아도 기능이 잘리지 않습니다. 긴 이미지·기기·모니터 이름과 버튼은 줄바꿈하고, 기기 카드·계정 창·탐색 상세·업로드·로그인 화면도 작은 폭과 가로 모드를 지원합니다. 화면 확대·회전 시 미디어 쿼리와 미리보기 크기가 갱신됩니다.

탐색은 내 이미지와 같은 카드 크기·태그·픽셀 해상도·적용 기술 배지를 사용한다. 업로드 체크 표시와 다운로드 수는 탐색 카드에 표시하지 않는다. 상세 패널은 첫 진입과 새로고침 시 숨기고, 이미지를 누르면 미리보기·작성자·해상도·파일 형식·전체 태그를 표시한다. 별도의 켜기/끄기 버튼과 화면 비율·다운로드 수·공유 취소·원본 이미지 열기 항목은 두지 않는다. 패널의 닫기 버튼이나 Esc로 닫으면 선택한 카드로 포커스가 돌아간다. 다른 사용자의 이미지는 내 이미지에 저장하거나 연결된 기기에 적용할 수 있다. 내가 공유한 이미지는 저장 버튼 없이 기존 원본을 작업실에서 연다. 새 이미지 작업실은 화면 높이에 맞추며 세로 페이지 스크롤을 없애고, 높이가 낮으면 최근 이미지·부가 안내를 접어 파일 선택 버튼을 유지한다.

탐색에서 기기에 적용할 때는 연결된 기기와 화면을 선택하고 확인한 뒤 내 계정으로 가져와 기존 기기 명령을 전송한다. 선택 취소나 연결 기기가 없는 경우에는 가져오기·명령을 만들지 않는다. Windows 모니터와 Android 홈·잠금 화면을 구분하고 오프라인·연결 해제·지원하지 않는 대상은 제외한다. 가져온 웹 결과물은 그대로 적용해 레이어·움직임을 보존하며 전송 재시도에서 가져오기를 중복하지 않는다. 실제 적용 완료는 연결 앱의 보고 후 확인한다.

작업실의 이미지 이름·편집 초기화·정보 표시줄은 중앙 편집 영역의 너비에 맞추고 오른쪽 이미지 설정 패널은 상단부터 전체 높이를 사용한다. 모든 편집 도구에 같은 배치를 적용하며 설정 내용만 필요할 때 스크롤한다. 루트와 설정 패널의 스크롤바 공간을 일정하게 유지해 내용 길이나 도구 전환으로 가로 위치가 바뀌지 않게 한다.

배경 분리는 RunPod의 BiRefNet_HR-matting + LaMa에 연결한다. [분리 워커 설정](../gpu-worker-runpod/layers/README.md)을 수동 배포하고 `RunPod__LayersEndpointId`를 설정해야 버튼이 활성화된다. 배경 분리의 마우스·자이로 입력과 공통 움직임 강도는 별도의 Live 2D 기능 상태와 분리해 저장한다. 두 입력을 함께 선택할 수 있으며 OFF에서도 분리 레이어는 보존한다. 웹 미리보기는 React를 매 프레임 렌더링하지 않고 `requestAnimationFrame`에서 GPU 합성 transform을 갱신한다. 휴대폰 브라우저는 HTTPS와 센서 지원/권한이 필요하며 기존 자이로 버튼에서 권한을 요청한다. 화면 주사율에 맞춰 60fps 이상을 목표로 하되 실제 기기 성능은 실측해야 한다.

운영 웹은 [CloudFront HTTPS 주소](https://d3bjir1z2hduu0.cloudfront.net/)로 접속한다. [자이로 연결·검증 기록](../docs/gyro-https-deployment-20261028.md)을 참고한다.

승인된 PC 웹 시안을 React·TypeScript·HTML·CSS로 구현한 프런트엔드입니다. C# API는 기존 서버를 그대로 사용합니다. 클라우드에서는 Nginx가 웹 파일을 제공하고 `/api`, `/hubs`, `/health`를 기존 API로 전달합니다.

## 화면과 동작

공유 버튼은 대화상자 없이 링크를 클립보드에 복사하고 마우스 위에 ‘링크가 복사되었습니다!’를 약 2.2초 표시합니다. 저장 및 내보내기는 하단 고정 영역에서 보관함에 저장 바로 위에 위치합니다. 태그 전체 선택은 13개 태그를 함께 선택·해제하고 부분 선택 상태도 표시합니다. 사진 이름의 연필 아이콘은 제거했습니다. 미리보기 배율 메뉴는 25%부터 200%까지 25% 간격이며 화면 맞춤은 별도 버튼으로만 실행합니다.

PNG 다운로드·편집 결과물 생성은 `/api/projects/{id}/content?jobId=...&layerId=...` 또는 `/api/wallpapers/{id}/content/{order}`에서 필요한 원본·완료 결과·레이어를 읽습니다(두 project 선택자는 함께 사용할 수 없습니다). 서버가 소유권·공개 상태를 확인하고 `private, no-store`로 응답하므로 S3 CORS 설정에 의존하지 않습니다. 공유 링크의 익명 다운로드는 `/api/wallpapers/links/{token}/content/{order}`가 해당 링크의 파일만 제공합니다. 현재 사진 이름과 필터·자르기·레이어 설정을 반영한 PNG를 브라우저 다운로드로 저장합니다.

작업실의 기본 도구는 업스케일이며 FHD/QHD/4K 버튼을 가로로 표시합니다. 적용 기기는 하단 버튼의 대화상자에서 선택합니다. 하단 버튼 순서는 ‘보관함에 저장 → 업로드하고 저장 → 연결된 기기에 적용’입니다. 필터 아래 태그 수정 도구와 1.2배 크기의 편집 가능한 사진 이름 필드를 제공하며, 보관함에 저장할 때 기존 프로젝트의 이름·태그·설정을 함께 갱신합니다. 적용한 기능 배지는 여러 개 함께 표시합니다.

공유는 `POST /api/wallpapers/{id}/share-link`로 비공개 불변 결과물에 256비트 임의 토큰을 발급하고 `/share/{token}`의 로그인 없는 보기 링크를 제공합니다. 탐색 공개 여부는 변경하지 않습니다. 링크는 해당 결과물을 보관함에서 삭제(보관 처리)할 때 무효가 됩니다. 탐색에 공개하는 기능은 업로드로 표시하며 공개 후 원본 편집 잠금은 유지합니다. `AddWallpaperShareLinks` migration이 필요합니다.

업로드는 JPEG, PNG, GIF, WebP, HEIF/HEIC, AVIF, BMP, TIFF 등을 지원하고 파일당 최대 50MiB입니다. 브라우저에서 먼저 디코딩하지 않으며 서버가 실제 파일을 읽어 방향·해상도를 확인하고 브라우저에서 표시할 수 있는 JPEG/PNG로 저장합니다. 애니메이션·다중 페이지 입력은 첫 프레임을 편집합니다. 최대 64MP·한 변 32768px를 유지하며 파일 한도를 넘는 요청이나 위장 파일은 저장 전에 거부합니다. Kestrel·multipart·Nginx 요청 한도는 multipart 부가 데이터 공간을 포함해 52MiB입니다.

- `/`: 소개 페이지, 화면 단위로 스크롤하는 기능 소개, 업스케일 전후 비교와 레이어 움직임 예시
- `/login`, `/signup`: 로그인, 가입·이메일 인증. 회원가입 안내 아래에 아이디 찾기·비밀번호 재설정 메뉴를 분리하며, 로그인 성공 후 항상 `/app/images`로 이동
- `/app/images`: 내 프로젝트와 저장된 배경화면 버전, 검색·정렬·다중 장르 필터. ‘이미지 추가’는 `/app/studio?new=1`의 새 이미지 작업실로 바로 이동. 카드 이름 아래에 실제 태그와 원본 픽셀 해상도 표시
- `/app/explore`: 기존 모바일 `/api/gallery` 게시물과 웹 `/api/wallpapers/shared` 배경화면을 함께 표시. 작성자·다중 장르를 유지하고 공개 게시물만 노출. 이미지를 누르면 오른쪽 상세를 열고 내 계정으로 가져오기 제공. 업로드 체크·다운로드 수·공유 취소·원본 이미지 열기·상세 전환 버튼은 표시하지 않음.
- `/app/studio`: 기본 진입 시 새 이미지 추가 화면을 표시. 사진을 선택하거나 `?id=...`로 열면 편집 시작. 업스케일·레이어 분리, Live 2D, 자르기·색감, 저장·공유·다운로드·기기 적용 제공
- `/app/devices`: 연결 앱 설치 안내·기기 자동 등록·연결 키 재발급, 모니터·홈·잠금 화면의 현재/대기 배경화면과 명령 상태. 기기 연결 버튼도 실제 다운로드와 같은 계정 로그인 안내를 제공하며 임의 해상도로 빈 기기를 생성하지 않음

앱 다운로드는 [Windows/Android 연결 앱](../docs/companion-apps.md)의 실제 배포 파일과 SHA-256 목록을 `/downloads/manifest.json`에서 읽습니다. iOS는 준비 중으로 표시합니다. 연결 앱에 같은 계정으로 로그인하면 기기를 자동 등록하며, 기기 관리에는 연결된 물리 화면 수·해상도·주사율·제조사·모델·OS·CPU 구조를 표시합니다. 홈/잠금 대상을 물리 화면 두 개로 계산하지 않습니다. Android 외부 화면은 정보 조회 전용입니다. 이 기능에는 `AddCompanionInventory` migration이 필요합니다.

기기 상태는 `/api/devices/updates`의 인증된 변경 알림으로 즉시 다시 읽습니다. 전체 이미지·공개 갤러리를 30초마다 다시 내려받는 경로를 제거하고 기기 정보만 갱신합니다. 창 복귀·재연결 시에도 갱신하며 동시 갱신은 합쳐 이전 응답이 최신 상태를 덮지 않도록 처리합니다. 연결 화면 수가 1/2/3개 이상이면 카드 폭을 단계적으로 넓히고, 내부 화면은 공간에 맞춰 줄바꿈합니다. 컨테이너 너비를 사용하므로 사이드바를 접거나 브라우저 폭을 바꿔도 맞춰집니다.

기기에 적용하는 불변 결과물은 원본 프로젝트와 **내 이미지 카드 하나**로 표시하고, 실제 결과물은 `library.assets`에 유지하여 현재/대기 미리보기와 작업실 링크에서 계속 사용합니다. 원본이 없는 가져온 결과물은 독립 카드로 남습니다. 적용 버튼에서 별도 저장을 먼저 실행하던 중복 경로를 제거했고, 같은 내용은 서버에서 재사용합니다(`reuseExisting`). 편집 픽셀을 굽기 위해 이번 작업이 새로 올린 임시 프로젝트만 결과물 복사 후 정리하며 기존 사용자 이미지는 삭제하지 않습니다. 이 변경에는 새 DB migration이 필요하지 않습니다.

왼쪽 메뉴는 완전히 숨길 수 있고 상태를 모든 앱 화면에서 공유합니다. 전역 헤더에 결과 공유·다운로드 버튼을 두지 않고 작업실 오른쪽에 배치했습니다. 좁은 브라우저에서도 내용이 겹치지 않게 최소한의 반응형 처리를 했으며 별도 모바일 UI/PWA 설치 기능은 이번 범위에 포함하지 않습니다.

작업실은 이전 사진을 자동 선택하지 않습니다. 기존 전역 헤더·왼쪽 앱 메뉴·색상은 유지하며 작업실은 문서 표시줄·세로 도구 막대·중앙 캔버스·오른쪽 단일 설정 패널로 구성합니다. 오른쪽 탭·중복 도구 제목·소개 문구와 이미지 아래 설명은 제거했습니다. 저장 전/저장됨 표시는 하단 파일 형식 오른쪽에 표시합니다. 이미지와 저장·기기 적용 버튼은 고정하고 설정 내용만 독립적으로 스크롤합니다.

업스케일은 배율 대신 FHD·QHD·4K를 선택합니다. 원본 비율을 유지하며 긴 변을 각각 1920·2560·3840px로 맞추고 실제 예상 출력 크기를 표시합니다. 현재 해상도 이하의 선택은 비활성화합니다. `targetLongEdge` 요청은 연결된 RunPod GPU의 Real-ESRGAN을 타일 단위로 실행하고 합성해 완성합니다. 로컬 데모는 실제 업스케일 요청을 실행하지 않습니다. 결과는 S3와 프로젝트 작업에 보존되며 목록·새로고침·PNG 다운로드에도 실제 결과 크기를 사용합니다. 서버에는 `AddUpscaleTargetResolution` migration 적용이 필요합니다. 자세한 워커 제한과 처리 방식은 [클라우드 처리 계약](../docs/cloud-processing.md)을 참고하세요.

저장 버튼은 ‘보관함에 저장’으로 표시하며 재편집도 같은 항목에 저장합니다. `PUT /api/projects/{id}/edit` 또는 `PUT /api/wallpapers/{id}/edit`로 기존 항목의 편집 설정과 UTC 저장 시각을 갱신합니다. 저장 버튼은 새 프로젝트·배경화면·S3 파일을 만들지 않으며 이미지 ID와 주소를 유지합니다. 서버의 소유자 검사·공유 잠금·설정 검증을 적용하고 새로고침/다른 브라우저에서도 저장한 편집 설정을 읽습니다. 원본 픽셀과 기기용 불변 manifest는 유지하며 PNG 다운로드·공유·기기 적용 시 기존 렌더링 경로에서 편집 설정을 반영합니다. 이 서버 저장에는 `20261027073746_SaveLibraryImageEdits` migration의 두 nullable `SavedEditJson` 컬럼이 필요하므로 API 배포 전에 기존 절차로 migration을 적용해야 합니다.

장르 선택은 모바일에서 사용한 13개 태그를 모두 제공하며 오른쪽 체크박스로 복수 선택합니다. 전체 선택은 모든 항목을 체크하고 미분류 이미지도 포함합니다. 선택이 없으면 ‘장르 없음’ 이미지로 자동 필터링하며 별도의 ‘장르 없음’ 선택 항목은 없습니다. 검색 아래의 중복 태그 줄과 격자/목록 전환 버튼은 제거했습니다. 이미지 태그와 부분 선택 요약은 5개까지만 표시하고 나머지는 `…`으로 줄이며, 원본 태그 데이터와 상세 화면에는 전체를 유지합니다.

탐색 공개 표시는 모바일 SharedBadge와 같은 ‘업로드 + 원형 체크’로 이미지 설정 메뉴 위에 배치합니다. 과거 모바일 공유 프로젝트의 태그·공유 여부는 같은 계정의 실제 갤러리 게시물과 프로젝트 ID로 연결합니다. 태그 정보가 없는 프로젝트/결과물을 임의로 풍경으로 분류하지 않습니다. 해상도는 API manifest의 실제 값 또는 전체 원본 이미지의 `naturalWidth`/`naturalHeight`를 사용하며 썸네일 표시 크기를 사용하지 않습니다. 모든 글자 크기는 rem과 `--font-scale: 1.3`으로 기존의 1.3배를 적용합니다.

## 개발 및 빌드

이미지 카드 설정의 공유 ON/OFF 스위치는 실제 공개 상태를 따릅니다. OFF에서는 이름 변경을 사용할 수 있고, ON에서는 이름 변경과 작업실의 편집·저장을 잠급니다. 카드의 이미지 설정 버튼은 항상 우측 하단에 고정되며, 메뉴는 다른 이미지·바깥 영역 선택 또는 Esc로 닫힙니다. 업로드 표시가 추가되어도 버튼과 메뉴 위치는 유지됩니다. 별도의 사진 설정 항목은 제거했으며 이미지나 제목을 누르면 작업실로 이동합니다. 미리보기·다운로드·기기 적용은 계속 사용할 수 있습니다. 미저장 변경은 먼저 저장한 뒤 공유하며, 저장 후에도 같은 이미지에서 편집을 이어갑니다. 원본 프로젝트에 공개된 배경화면 버전이 여러 개 있으면 모두 공유를 끌 때까지 잠금을 유지합니다.

비공개 이름 변경은 `PATCH /api/projects/{id}` 또는 `PATCH /api/wallpapers/{id}`의 `{ title }` 요청으로 서버에 저장합니다. API는 소유자 확인과 길이(1~160자)·공유 상태 검증을 수행합니다. 이름 변경으로 픽셀과 manifest는 바뀌지 않습니다. 본인의 결과물 목록에는 `sourceProjectId`가 포함되고 공개 목록에는 원본 ID를 노출하지 않습니다. 편집 결과를 별도 프로젝트로 업로드할 때 `originProjectId`로 본인 소유 원본과 연결합니다. 새 DB 컬럼이나 migration은 필요하지 않습니다.

Node.js 22.12 이상 또는 24, pnpm 11을 사용합니다. 의존성은 `pnpm-lock.yaml`에 고정했습니다.

```powershell
cd web
pnpm install --frozen-lockfile
pnpm dev
```

기본 개발 주소는 `http://localhost:5173`입니다. 기본 `public/config.js`는 **브라우저 로컬 데모**를 선택합니다. 로그인 화면의 ‘데모 계정 입력’으로 화면 동작을 확인할 수 있습니다. 이 계정은 서버 인증 정보가 아니며 클라우드 데이터에 접근하지 못합니다. 업로드는 브라우저 저장 공간에 맞게 축소하고, AI 처리·실제 기기 적용은 실행하지 않습니다.

```powershell
# TypeScript 검사 + 일반 빌드
pnpm build
# TypeScript 검사 + 같은 origin의 실제 API를 사용하는 클라우드 빌드
pnpm build:cloud
```

`build:cloud`는 산출물 `dist/config.js`를 `{ mode: "cloud", apiBaseUrl: "" }`로 설정합니다. 서버 주소·비밀값을 번들에 하드코딩하지 않습니다. 다른 API origin을 사용할 때만 배포된 `config.js`의 `apiBaseUrl`을 설정하고 API/S3 CORS를 맞추세요. Vite의 `VITE_` 변수와 `config.js`는 공개 설정이므로 비밀번호·JWT secret·공급자 키를 넣으면 안 됩니다.

## 실제 API 연결

클라우드 모드는 데이터 조회에 실패했을 때 데모 데이터로 대체하지 않고 연결 오류를 표시합니다. 사용자 소유권 검증은 API가 수행합니다. 기본 토큰 저장은 `sessionStorage`이며 ‘자동 로그인’을 선택한 경우에만 `localStorage`를 사용합니다. 만료 시 refresh 요청을 한 번으로 묶어 재시도하고, 세션 종료 시 로그인 화면으로 돌아갑니다. 자동 갱신은 현재 화면을 바꾸지 않습니다.

‘아이디 저장’과 ‘자동 로그인’은 같은 줄에 왼쪽 정렬하고 독립적으로 처리합니다. 로그인 성공 시 사용자가 입력한 문자열을 그대로 브라우저에 저장하므로 이메일로 로그인하면 이메일, 아이디로 로그인하면 아이디가 다음 로그인 화면에 표시됩니다. 서버가 반환한 정규화 이메일로 바꾸지 않으며 비밀번호는 저장하지 않습니다. 체크 해제 시 저장된 입력값을 즉시 삭제하고, 로그아웃은 저장한 아이디를 유지합니다. 저장 공간 차단으로 이 선택 기능을 이용할 수 없어도 로그인은 계속 진행합니다.

계정 복구는 모바일과 같은 기존 API를 사용합니다. `/api/auth/find-id`에 가입 이메일을 보내 인증 완료 계정의 사용자 아이디 또는 일치 계정 없음 결과를 표시합니다. `/api/auth/forgot-password`로 6자리 인증 코드를 요청하고 `/api/auth/reset-password`로 코드·새 비밀번호를 제출합니다. 새 비밀번호 확인 및 기존 10~128자·대문자·숫자·특수문자 정책을 적용하고, 코드 확인 단계에서는 이메일을 고정합니다. 이메일 변경은 코드 입력 단계를 초기화하며 재전송도 제공합니다. 코드·새 비밀번호는 저장 공간에 기록하지 않습니다. 로컬 데모는 계정 복구 API와 이메일 발송을 제공하지 않습니다.

이미지는 multipart `/api/projects`로 업로드하고 서버의 S3 서명 URL을 사용합니다. 처리 작업은 `/process` 요청 후 상태를 조회합니다. Live 2D는 서버가 반환한 배경과 전경 레이어를 합성합니다. 필터·자르기는 브라우저 Canvas로 렌더링해 PNG로 다운로드하고, 그 상태로 공유/적용할 때는 새 프로젝트를 업로드해 고정된 결과물을 만듭니다. Live 2D 움직임은 PNG에 포함되지 않습니다. PNG 내보내기 최대 긴 변은 4,096px이며 고해상도 AI 원본 파일 전달은 후속 다운로드 UX에서 확장할 수 있습니다.

기기 연결 키는 명시적 발급/재발급 시 메모리와 대화상자에만 보관합니다. 연결 앱은 같은 계정의 유효한 로그인과 기기 자격을 함께 사용해야 합니다. 웹은 적용 요청을 전송하며 **기기 보고 전에는 완료로 표시하지 않습니다**. 기기 화면은 30초 간격과 수동 새로고침으로 갱신됩니다.

## 수동 클라우드 배포

자동 배포나 CI는 추가하지 않았습니다. [Nginx 예시](../deploy/nginx-web.conf.example)와 [수동 설치 스크립트](../deploy/install-web.sh)를 사용합니다. 빌드 결과를 압축해 기존 Ubuntu 서버로 전달한 뒤 다음처럼 실행합니다. 실제 경로·호스트는 환경에 맞게 지정하세요.

```powershell
pnpm build:cloud
tar -czf ../tmp/upscale-web.tar.gz -C dist .
# scp -i "개인키_경로" ... ubuntu@SERVER:/home/ubuntu/UPLOAD_DIRECTORY/
```

```bash
bash install-web.sh /absolute/upscale-web.tar.gz /absolute/nginx-web.conf.example web-YYYYMMDD-HHMMSS
```

설치 스크립트는 `/var/www/upscale-lab/releases/`에 새 버전을 풀고 `current` 링크를 교체합니다. 기존 Nginx 설정을 `$HOME/deploy-backups/web/<release>/`에 백업하고 `nginx -t` 후 재적재합니다. API 소스·실행 파일·서비스·DB·클라우드 AI 설정을 수정하지 않습니다. 기존 서버에 필요한 다른 Nginx 규칙이 있다면 예시를 먼저 조정해야 합니다. 현재 예시는 기존 HTTP 점검 서버의 프록시 동작을 보존하며, 정식 운영 전에 실제 TLS 종료 구성으로 전환해야 합니다.

## 검증 및 남은 범위

```powershell
$env:WEB_TEST_URL='https://YOUR_TEST_WEB_ORIGIN'
pnpm test
```

실서버 smoke test 11개는 페이지/번들·새 작업실 진입 경로·cloud 설정·직접 진입·health·미인증 차단·공유 JSON·이름 변경 PATCH 등록 및 인증·기존 모바일 게시물 표시·로그인/계정 복구 입력 검증·404 라우팅을 검사합니다. 계정 생성, 메일 발송, 비밀번호 변경, 데이터 삭제, 유료 AI 작업은 실행하지 않습니다. `WEB_TEST_URL`이 없으면 실서버 테스트만 건너뛰고 탐색·공유 잠금·이미지 정보·태그·아이디 저장·비밀번호 정책 회귀 테스트 25개는 실행합니다. 로그인한 실서버 계정의 업로드→AI 결과→공유→실제 연결 앱 적용 및 메일 수신 후 비밀번호 변경은 전용 테스트 계정과 기기로 추가 검증해야 합니다.

기존 모바일 게시물은 게시물 ID를 유지하며 다른 사용자의 프로젝트 ID를 편집 권한으로 재사용하지 않습니다. 가져오기는 원본을 읽어 현재 계정의 새 프로젝트로 업로드합니다. 원본 파일 읽기에는 S3가 웹 origin의 GET CORS를 허용해야 하며, 허용되지 않으면 다시 시도하라는 오류를 표시합니다. 게시물 표시 자체에는 S3 CORS 변경이나 DB 이관이 필요하지 않습니다. 탐색에는 별도의 공유 취소 기능을 두지 않으며 내 이미지의 업로드 관리는 유지합니다.

문의는 현재 브라우저에 임시 저장하며 메일은 발송하지 않습니다. 연결 앱 설치 파일은 배포 준비 중으로 표시합니다. 실제 명령 API가 생성 시간을 반환하지 않아 적용 내역의 요청 시간은 `—`로 표시하며 완료/실패/기기 확인 필요 상태는 서버 응답을 따릅니다.

샘플 이미지 출처와 생성 프롬프트는 [ASSETS.md](ASSETS.md)를 참고하세요.

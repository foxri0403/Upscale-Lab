# Upscale Lab mobile client

This Flutter client supports JWT login with optional secure auto-login, local-first image registration, explicit cloud sharing, per-image share/delete actions, static wallpaper previews, a sensor-filtered layer preview, and an Android live wallpaper backed by locally cached project layers and `WallpaperService`.

Image registration uses a fixed layout without vertical scrolling, with transparent editing panels and tool backgrounds. Photo information, filters, and ratio controls sit directly above the bottom tools; the photo uses all remaining space at its current aspect ratio, without a percentage or 360-pixel height cap. Landscape layouts put the save action beside the tool strip and arrange name/tag fields side by side to preserve preview height. Tap the photo in any tool to view the current crop and filter in a full-screen preview with pinch zoom. The crop tool always shows its ratio presets and orientation controls, with a compact text-only **자동** action and no manual-mode button. Choosing a preset/orientation applies it immediately; **자동** restores the current device display ratio and follows display rotation. **태그** opens the same multi-select popup as Explore, including **전체 태그**, **초기화**, and **적용하기**; closing without applying preserves the previous selection. Horizontal tool/filter/ratio strips and the tag popup remain scrollable. Controls that exceed a compact viewport are clipped. These source changes can be tested in Android Studio without generating an APK or changing the app version.

The static wallpaper service supports home-only, lock-only, and both-screen application and removal. UI target selectors can use the typed Dart service and account-scoped library method documented in [Wallpaper API integration](docs/wallpaper-api.md). Existing home-only UI behavior remains available.

Auto-login now renews expired access tokens with a secure refresh credential and keeps saved sessions during temporary network failures. It requires the matching backend and `AddPersistentAuthSessions` migration; existing saved logins without a refresh credential need one fresh login with auto-login selected after their access token expires. Email verification expires 15 minutes after registration, and unverified accounts are cleaned automatically by the API. See [server setup and expiration policy](../docs/auth-sessions.md), including required Cognito admin permissions.

The local home library has a text sorting menu beside **내 이미지 (N)**: **사용자순**, **등록순**, **오래된순**, **가나다순**, **ABC순**. Korean sorting puts Hangul before English; ABC sorting puts English first, ignoring letter case. Long-press an image in either layout to drag it onto another position; dragging from any other sort snapshots the currently displayed order and switches to **사용자순**. The chosen sort and manual order are written to account/server-scoped persistent Android preferences, survive logout and restart, and keep new images after previously arranged images. Thumbnails are square with sharp corners; the original file is preserved.

Tapping a registered image opens the app's full-screen preview with **홈 화면**, **잠금 화면**, and **홈 화면 및 잠금 화면** targets. All previews fit the complete image at its original aspect ratio; application uses the saved **자동 / 수동** wallpaper ratio. Automatic uses the full device display and follows rotation; manual keeps the saved preset or editor free-crop ratio. **배경화면 설정** applies the selected target without modifying the source. Home preview controls stay below the image, and completion feedback does not cover the apply button. Explore always displays two columns of square thumbnails with narrow gutters, a title strip over the bottom edge, and the persisted download count at the upper right. Thumbnails fill their square; the original file is unchanged. Home layout toggles do not appear in Explore. A compact search field and tag button preserve title/tag filtering. Shared images open a full-screen original-aspect preview with pinch zoom and a translucent bottom panel containing the uploader, tags, ratio settings, wallpaper application, and library save action. Drag the panel or swipe the photo down at its original zoom to hide the panel; drag/swipe up or tap the long bottom handle to restore it. The handle remains visible when the panel is hidden. Hiding the panel preserves the chosen ratio and keeps the preview open. Loading failures offer retry and disable apply/save until an image loads.

Android Studio validation: reopen the app after an access token expires with auto-login enabled, test a temporary offline launch, check sort/drag persistence after logout/login in both layouts, and check automatic wallpaper cropping on portrait, landscape, and tablet displays. Open the keyboard and try split screen to verify that automatic ratios still use the full display. Save a manual ratio, reopen image editing, and switch back to automatic. APK generation is not required for these source changes.

Installable APK deliverables use the `Upscale_Lab-<version>-.apk` naming convention. The current app version is `0.12.1` with Android build number `21`; the APK is `artifacts/Upscale_Lab-0.12.1-.apk`. This release fixes Live 2D selection/sensor lifecycle on the actual wallpaper and moves image storage to private app files, with verified migration of existing album copies. Read the current version and versioning rules in the root `AGENTS.md` before generating an APK, and replace its latest-version entry after every build.

New shares also persist the complete tag set in versioned description metadata for legacy single-tag servers. The app verifies the persisted response and reconstructs tags when another client reads the post. Search supports any-of multi-selection and keeps tags/title when switching tabs. Legacy servers can filter only the primary tag, so secondary-tag filtering is performed by the app within the returned posts; full server-side filtering and shared tag editing require the matching backend. Upgraded servers read compatibility metadata on old posts and remove it on native tag edits.

Image registration and editing support multiple genre tags. **검색** supports multiple independent tag filters: a post appears if it matches any selected tag and the title search. Shared name/tag edits save locally only after the backend confirms both the name and the entire selected tag set. The matching backend provides `PATCH /api/gallery/{id}` for these combined edits; older servers show an update-required error without changing local metadata. Tap a shared image to download its original, preview/apply it as the home wallpaper, and select **내 보관함에 저장** to keep a private local copy. Imported copies are not linked to the uploader's cloud project or shared automatically.

Native tag arrays, shared tag editing, filtering across the full gallery, and thumbnails require the matching backend and the `AddGalleryMultiTags` migration, which copies existing single tags into the new array. `PATCH /api/gallery/{id}/tag` accepts `tags` (the legacy `tag` remains compatible), and `GET /api/gallery?tags=동물&tags=풍경` matches any requested tag. `GET /api/gallery/{id}/thumbnail` generates a JPEG with a maximum side of 480 pixels on first access, persists it in S3, and uses a bounded 64 MiB server cache for repeat requests. The client uses a stable thumbnail URL and bounds decoded preview size; original downloads occur on import. Preview access does not count as a download. Unsupported/corrupt image formats fall back to the original. The first thumbnail generation and original download still depend on image size and network speed. Deploy the backend and apply the migration manually after checking the target DB and backup; the APK alone cannot add server capabilities.

The home library now stores untouched image copies and separate JSON metadata in permanent app-private `files/image_library/<owner>/<image>/` directories. New registrations and saved gallery imports never publish to MediaStore, never scan media, and are not visible as new images in the device gallery. Account identity, tags, ratio, UTC timestamps, share links and Live 2D mode remain durable across cache clearing, logout and restart. Ordinary library actions require no gallery/storage permission. App-data clearing or uninstall removes private library files. Existing account-owned copies in `Pictures/Upscale Lab` are migrated after verifying the internal copy, then removed from that album; Android may require deletion consent. **설정 → 기존 갤러리 이미지 이전** retries migration when photo access or consent is needed. Selected source photos and other users' records are preserved. See [private image storage and migration](../docs/private-image-storage.md).
**삭제** removes only the current account's on-device image. Shared cloud posts and projects remain available; **공유 취소** is the separate action that removes those server resources while keeping the device image. A timeout during sharing or failure to persist its private share metadata does not automatically delete a possibly published cloud post. See [local deletion policy](../LOCAL_DELETE_POLICY.md).

Release APKs now use the team's shared signing key. Copy `android/key.properties.example` to the ignored `android/key.properties` and fill its four fields locally, or point `UPSCALE_SIGNING_PROPERTIES_FILE` at an external properties file. Relative keystore paths resolve beside that properties file. Alternatively use `UPSCALE_KEYSTORE_FILE`, `UPSCALE_KEYSTORE_PASSWORD`, `UPSCALE_KEY_ALIAS`, and `UPSCALE_KEY_PASSWORD`; these override the local properties. Missing shared credentials fail release signing rather than falling back to the machine's debug key. Debug builds keep their usual debug signing. Never commit keystores or credentials. Verify every generated APK with Android `apksigner` and compare its certificate with the intended shared key. Existing team APKs used a debug certificate; a different shared certificate cannot directly update those installations without a compatible signing lineage.

Registration, metadata editing, and the tag picker omit `장르 설정되지 않음` from their selectable options. Saving image metadata with no selected tags supplies that fallback automatically. Empty search-tag selection still means no filter.

Gallery cards and previews display a numeric `downloadCount`, defaulting to `0`. Completed original downloads are recorded in the existing server field; thumbnail/preview URL requests are not counted. The API preserves legacy client behavior and needs a manual deployment for completion reporting; no new database migration is required. See [download-count API and compatibility](../docs/gallery-download-counts.md).

## Run

Install a current Flutter SDK, then run:

```powershell
cd mobile
flutter pub get
flutter analyze
flutter run --dart-define=API_BASE_URL=http://YOUR_API_HOST:5080
```

The emulator default in `main.dart` is `http://10.0.2.2:5080`. A physical device must use a reachable HTTPS API URL.

The login screen includes **서버 주소 설정**. Team test builds persist the selected API URL in Android app preferences, so the same APK can switch from a local server to the final AWS HTTPS endpoint without rebuilding. Changing the server logs out the current session.

The home screen uses one local-first library. Registering an image saves an account-owned copy in permanent app-private files and never calls an upload API. The registration screen pre-fills the original filename, lets the user edit it, and stores multiple searchable genre tags and ratio settings. The upper-right controls switch between a one-column thumbnail list and a two-column grid in both Home and Search. Unshared items display only their name and tags; shared library items add a right-aligned **공유** label and a blue circle with a white check in the name row. The three-dot menu contains **공유** (or **공유 취소** for shared items), **수정**, and **삭제**. **수정** edits the name, tags, and wallpaper ratio together. Ratio settings stay in its private JSON metadata; shared name/tag edits still require backend confirmation before saving locally. **설정 → 홈 배경화면 제거** restores Android's default home wallpaper without deleting registered images. Sharing is the only action that uploads the image to S3, creates its server project, and publishes the gallery item. Sharing cancellation removes the public gallery post and cloud project while preserving the device copy; local deletion preserves the cloud copy. The Search tab (**탐색**) lists public cloud posts, searches image titles only, and applies any-of exact tag filtering in both the API and client.

All screens use the shared bright theme in `lib/theme/app_theme.dart`, including account forms, search, registration, dialogs, settings, and previews. Android system bars remain visible; Flutter reserves their safe-area insets below the app tabs and actions. For three-button navigation, select that navigation mode in the device/emulator's Android settings; the app does not replace the system buttons. UI-only development can run directly from Android Studio by opening `mobile`, selecting the Flutter SDK and an emulator, and running `lib/main.dart`. An APK release and version increment are unnecessary for this workflow.

After image selection, **새 이미지 등록** combines **사진 정보**, **자르기**, and **필터** in one editor. Its camera-style bottom tool row scrolls horizontally; settings change inline, while **저장** stays at the bottom. **사진 정보** edits the name and multiple genre tags. Korean tags are in 가나다 order, followed by English tags in ABC order; an empty selection is saved as `장르 설정되지 않음`. Information and filter previews show the entire current image/crop inside a bounded viewport at its own aspect ratio. Vertical drags scroll the page; only the crop tool captures photo gestures. The crop canvas fits the space remaining above the toolbar/save button, while ratio and filter settings remain reachable by scrolling. Filter thumbnails also preserve the original aspect ratio. **자르기** enables draggable crop corners and pinch/drag adjustments with automatic or manual ratios, original/free presets, orientation, and fixed ratios. **필터** previews original, vivid, soft, monochrome, and sepia effects. Switching tools preserves the name, tags, crop, and filter. **Live 2D** opens on-device two-layer separation, tilt preview, and live wallpaper saving/application. **업스케일** retains the existing server processing flow. See [Live 2D](../docs/live-2d.md) for requirements, storage, sensor behavior, and limitations.

**저장** opens **배경화면 적용** with two independent checkboxes, **홈 화면** and **잠금 화면**, initially unchecked. Home only displays `홈화면의 배경화면을 바꿉니다.`, lock only `잠금화면의 배경화면을 바꿉니다.`, both `홈/잠금 화면을 바꿉니다.`, and neither `배경화면을 바꾸지 않고 이미지만 저장합니다.`. **취소** returns to editing without saving or applying anything. Confirming **저장** exports any crop/filter edits and imports a copy into the account-owned app-private folder with separate JSON metadata. Unedited images retain their original bytes and extension; edited images use the editor export format. The selected source file is never overwritten. Only after import succeeds does the app apply the saved image to the checked screens. Neither checked means save only. Wallpaper application failure preserves the saved image and offers retry from Home. There is no separate **화면 적용** tool.

The editor supports finger pinch-to-zoom, dragging the image, and dragging crop corners. **비율** is split into **자동 / 수동**. Automatic constrains the crop to the detected full display, follows screen rotation, and hides manual orientation and preset controls. Android uses [maximum window metrics](https://developer.android.com/reference/android/view/WindowManager#getMaximumWindowMetrics()) on API 30+ and real display metrics on older versions; system bars, keyboard insets, and the app's split-screen window do not define the ratio. The manual horizontal choices are **원본 → 자유 형태 → 9:16 / 16:9 → 3:4 / 4:3 → 1:1**. Portrait/landscape changes both labels and actual crop constraints. Original uses the source aspect ratio, and free permits independent width/height changes and saves the resulting ratio. The former fit-shape preset has been removed. Viewport changes preserve the selected source region. Existing records without ratio metadata default to automatic. The legacy **변환 방식** editor offers original, the existing pending upscale button, and an enabled **Live 2D** button connected to the same separation preview. Live 2D replaces the former 2.5D name.

**필터** and **자르기** share a centered tool row. Filters preview immediately and are baked into the saved pixels: **원본**, **선명** (increased contrast/saturation), **차분** (reduced contrast/saturation), **흑백** (luminance), and **세피아** (brown monochrome). This selection follows the filter/color-adjustment categories described by [Samsung Gallery](https://www.samsung.com/ae/support/mobile-devices/samsung-gallery-editing-a-photo/), [Google Photos](https://support.google.com/photos/answer/6128850), and [Apple Photos](https://support.apple.com/en-gb/guide/iphone/iphb08064d57/ios). It uses custom color matrices, not replicas of proprietary presets; near-duplicate warm/cool and monochrome variants are omitted. Previews are decoded to a maximum side of 1600 pixels, while export crops from the full-resolution source. Edited copies are lossless PNGs (the first frame for animated sources), saved to a temporary app-cache folder and imported into the existing account-scoped library. The original is never overwritten, and the temporary copy is removed after import or cancellation. Finishing without pixel edits preserves the original file format.

The login screen includes **자동 로그인**. When selected, the JWT and expiration are stored with Android's secure storage and verified against `/api/auth/me` at the next launch. Logging out, changing the server address, token expiration, or validation failure clears the saved session.

Static wallpaper application keeps a persistent app-private source copy before handing it to Android's `WallpaperManager`; Android keeps the applied wallpaper after the app exits and across device restarts. **라이브 배경화면 적용** downloads processed layers into app-private persistent storage before opening Android's required live-wallpaper confirmation screen. `WallpaperService` reloads that saved manifest and cached layers whenever Android recreates it, including after reboot.

Download and wallpaper actions refresh the project first because the S3 image links are short-lived. Android preserves the original extension and MIME type for the mobile image formats accepted by the backend, including HEIC/HEIF and AVIF.

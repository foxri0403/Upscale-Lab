# Upscale Lab mobile client

This Flutter client supports JWT login with optional secure auto-login, local-first image registration, explicit cloud sharing, per-image share/delete actions, static wallpaper previews, a sensor-filtered layer preview, and an Android live wallpaper backed by locally cached project layers and `WallpaperService`.

The static wallpaper service supports home-only, lock-only, and both-screen application and removal. UI target selectors can use the typed Dart service and account-scoped library method documented in [Wallpaper API integration](docs/wallpaper-api.md). Existing home-only UI behavior remains available.

Auto-login now renews expired access tokens with a secure refresh credential and keeps saved sessions during temporary network failures. It requires the matching backend and `AddPersistentAuthSessions` migration; existing saved logins without a refresh credential need one fresh login with auto-login selected after their access token expires. Email verification expires 15 minutes after registration, and unverified accounts are cleaned automatically by the API. See [server setup and expiration policy](../docs/auth-sessions.md), including required Cognito admin permissions.

The local home library has a text sorting menu beside **내 이미지 (N)**: **사용자순**, **등록순**, **오래된순**, **가나다순**, **ABC순**. Korean sorting puts Hangul before English; ABC sorting puts English first, ignoring letter case. Long-press an image in either layout to drag it onto another position; dragging from any other sort snapshots the currently displayed order and switches to **사용자순**. The chosen sort and manual order are written to account/server-scoped persistent Android preferences, survive logout and restart, and keep new images after previously arranged images. Thumbnails are square with sharp corners; the original file is preserved.

Tapping a registered image opens the app's full-screen preview with **홈 화면**, **잠금 화면**, and **홈 화면 및 잠금 화면** targets. The preview and account-scoped native application use the saved **자동 / 수동** ratio: automatic uses the full device display and follows rotation; manual keeps the saved original, portrait/landscape 9:16, 3:4, 1:1, or editor free-crop ratio. **배경화면 설정** applies the selected target without modifying the source. The preview menu offers edit, share/unshare, and local deletion. Shared-image previews also support automatic/manual ratios, and **내 보관함에 저장** keeps the selected ratio with the imported copy. Shared-preview loading failures offer retry and disable apply/save until an image loads.

Android Studio validation: reopen the app after an access token expires with auto-login enabled, test a temporary offline launch, check sort/drag persistence after logout/login in both layouts, and check automatic wallpaper cropping on portrait, landscape, and tablet displays. Open the keyboard and try split screen to verify that automatic ratios still use the full display. Save a manual ratio, reopen image editing, and switch back to automatic. APK generation is not required for these source changes.

Installable APK deliverables use the `Upscale_Lab-<version>-.apk` naming convention. The current app version is `0.9.0` with Android build number `16`; the APK is `artifacts/Upscale_Lab-0.9.0-.apk`. Read the current version and versioning rules in the root `AGENTS.md` before generating an APK, and replace its latest-version entry after every build.

New shares also persist the complete tag set in versioned description metadata for legacy single-tag servers. The app verifies the persisted response and reconstructs tags when another client reads the post. Search supports any-of multi-selection and keeps tags/title when switching tabs. Legacy servers can filter only the primary tag, so secondary-tag filtering is performed by the app within the returned posts; full server-side filtering and shared tag editing require the matching backend. Upgraded servers read compatibility metadata on old posts and remove it on native tag edits.

Image registration and editing support multiple genre tags. **검색** supports multiple independent tag filters: a post appears if it matches any selected tag and the title search. Shared name/tag edits save locally only after the backend confirms both the name and the entire selected tag set. The matching backend provides `PATCH /api/gallery/{id}` for these combined edits; older servers show an update-required error without changing local metadata. Tap a shared image to download its original, preview/apply it as the home wallpaper, and select **내 보관함에 저장** to keep a private local copy. Imported copies are not linked to the uploader's cloud project or shared automatically.

Native tag arrays, shared tag editing, filtering across the full gallery, and thumbnails require the matching backend and the `AddGalleryMultiTags` migration, which copies existing single tags into the new array. `PATCH /api/gallery/{id}/tag` accepts `tags` (the legacy `tag` remains compatible), and `GET /api/gallery?tags=동물&tags=풍경` matches any requested tag. `GET /api/gallery/{id}/thumbnail` generates a JPEG with a maximum side of 480 pixels on first access, persists it in S3, and uses a bounded 64 MiB server cache for repeat requests. The client uses a stable thumbnail URL and bounds decoded preview size; original downloads occur on import. Preview access does not count as a download. Unsupported/corrupt image formats fall back to the original. The first thumbnail generation and original download still depend on image size and network speed. Deploy the backend and apply the migration manually after checking the target DB and backup; the APK alone cannot add server capabilities.

The home library now uses the device's public `Pictures/Upscale Lab` album as its source of truth. Each image embeds a SHA-256 comparison key derived from the authenticated JWT subject alongside its image ID, title, tags, ratio, timestamps and share links in PNG iTXt or JPEG APP15 metadata. Existing EXIF UserComment records remain readable for compatibility. The app filters records by that account; the original photos remain visible in the device gallery, and metadata filtering is not encryption or a security boundary against other gallery apps. Album ownership is independent of the API host; the existing server/account scope still namespaces sorting and migration. App-cache copies are disposable upload/wallpaper inputs. Images saved in this album can reappear after reinstalling and signing in with the same account when full photo access is granted. Existing app-private records migrate once after an update, only for their original account; unowned legacy records remain untouched. See [gallery restore notes](../GALLERY_AUTO_RESTORE_NOTES.md) for permissions and device verification.

**삭제** removes only the current account's on-device image. Shared cloud posts and projects remain available; **공유 취소** is the separate action that removes those server resources while keeping the device image. A timeout during sharing or failure to persist its embedded share marker does not automatically delete a possibly published cloud post. See [local deletion policy](../LOCAL_DELETE_POLICY.md).

Release APKs now use the team's shared signing key. Copy `android/key.properties.example` to the ignored `android/key.properties` and fill its four fields locally, or point `UPSCALE_SIGNING_PROPERTIES_FILE` at an external properties file. Relative keystore paths resolve beside that properties file. Alternatively use `UPSCALE_KEYSTORE_FILE`, `UPSCALE_KEYSTORE_PASSWORD`, `UPSCALE_KEY_ALIAS`, and `UPSCALE_KEY_PASSWORD`; these override the local properties. Missing shared credentials fail release signing rather than falling back to the machine's debug key. Debug builds keep their usual debug signing. Never commit keystores or credentials. Verify every generated APK with Android `apksigner` and compare its certificate with the intended shared key. Existing team APKs used a debug certificate; a different shared certificate cannot directly update those installations without a compatible signing lineage.

## Run

Install a current Flutter SDK, then run:

```powershell
cd mobile
flutter pub get
flutter analyze
flutter run --dart-define=API_BASE_URL=http://YOUR_API_HOST:5080
```

The emulator default in `main.dart` is `http://10.0.2.2:5080`. A physical device must use a reachable HTTPS API URL.

The login screen includes **서버 주소 설정**. Team test builds persist the selected API URL in Android app preferences, so the same APK can switch from a local server to the final AWS HTTPS endpoint without rebuilding. Changing the server logs out the current session.

The home screen uses one local-first library. Registering an image saves an account-marked copy in `Pictures/Upscale Lab` and never calls an upload API. The registration screen pre-fills the original filename, lets the user edit it, and stores multiple searchable genre tags and ratio settings. The upper-right controls switch between a one-column thumbnail list and a two-column grid in both Home and Search. Unshared items display only their name and tags; shared library items add a right-aligned **공유** label and a blue circle with a white check in the name row. The three-dot menu contains **공유** (or **공유 취소** for shared items), **수정**, and **삭제**. **수정** edits the name, tags, and wallpaper ratio together. Ratio settings stay in the image's embedded metadata; shared name/tag edits still require backend confirmation before saving locally. **설정 → 홈 배경화면 제거** restores Android's default home wallpaper without deleting registered images. Sharing is the only action that uploads the image to S3, creates its server project, and publishes the gallery item. Sharing cancellation removes the public gallery post and cloud project while preserving the device copy; local deletion preserves the cloud copy. The Search tab (**탐색**) lists public cloud posts, searches image titles only, and applies any-of exact tag filtering in both the API and client.

All screens use the shared bright theme in `lib/theme/app_theme.dart`, including account forms, search, registration, dialogs, settings, and previews. Android system bars remain visible; Flutter reserves their safe-area insets below the app tabs and actions. For three-button navigation, select that navigation mode in the device/emulator's Android settings; the app does not replace the system buttons. UI-only development can run directly from Android Studio by opening `mobile`, selecting the Flutter SDK and an emulator, and running `lib/main.dart`. An APK release and version increment are unnecessary for this workflow.

After image selection, **새 이미지 등록** combines **사진 정보**, **자르기**, and **필터** in one editor. Its camera-style bottom tool row scrolls horizontally; settings change inline, while **저장** stays at the bottom. **사진 정보** edits the name and multiple genre tags. Korean tags are in 가나다 order, followed by English tags in ABC order; an empty selection is saved as `장르 설정되지 않음`. Portrait previews fit the available width without sidebars and support pan/zoom to inspect the complete image. Preview-only pan/zoom never changes saved pixels. **자르기** enables draggable crop corners and pinch/drag adjustments with automatic or manual ratios, original/free presets, orientation, and fixed ratios. **필터** previews original, vivid, soft, monochrome, and sepia effects. Switching tools preserves the name, tags, crop, and filter. **업스케일** and **2.5D** are disabled **준비 중** buttons only; no processing is implemented.

**저장** opens **배경화면 적용** with two independent checkboxes, **홈 화면** and **잠금 화면**, initially unchecked. Home only displays `홈화면의 배경화면을 바꿉니다.`, lock only `잠금화면의 배경화면을 바꿉니다.`, both `홈/잠금 화면을 바꿉니다.`, and neither `배경화면을 바꾸지 않고 이미지만 저장합니다.`. **취소** returns to editing without saving or applying anything. Confirming **저장** exports any crop/filter edits and imports a copy into the account-filtered gallery album with its embedded metadata. JPEG/PNG copies retain their image pixels when unedited; other supported formats are normalized to PNG for writable metadata, using the first frame for animated images. The selected source file is never overwritten. Only after import succeeds does the app apply the saved image to the checked screens. Neither checked means save only. Wallpaper application failure preserves the saved image and offers retry from Home. There is no separate **화면 적용** tool.

The editor supports finger pinch-to-zoom, dragging the image, and dragging crop corners. **비율** is split into **자동 / 수동**. Automatic constrains the crop to the detected full display, follows screen rotation, and hides manual orientation and preset controls. Android uses [maximum window metrics](https://developer.android.com/reference/android/view/WindowManager#getMaximumWindowMetrics()) on API 30+ and real display metrics on older versions; system bars, keyboard insets, and the app's split-screen window do not define the ratio. The manual horizontal choices are **원본 → 자유 형태 → 9:16 / 16:9 → 3:4 / 4:3 → 1:1**. Portrait/landscape changes both labels and actual crop constraints. Original uses the source aspect ratio, and free permits independent width/height changes and saves the resulting ratio. The former fit-shape preset has been removed. Viewport changes preserve the selected source region. Existing records without ratio metadata default to automatic. **변환 방식** contains original, upscale, and 2.5D buttons; upscale and 2.5D are explicitly marked **준비 중** and do not process images or record a conversion mode.

**필터** and **자르기** share a centered tool row. Filters preview immediately and are baked into the saved pixels: **원본**, **선명** (increased contrast/saturation), **차분** (reduced contrast/saturation), **흑백** (luminance), and **세피아** (brown monochrome). This selection follows the filter/color-adjustment categories described by [Samsung Gallery](https://www.samsung.com/ae/support/mobile-devices/samsung-gallery-editing-a-photo/), [Google Photos](https://support.google.com/photos/answer/6128850), and [Apple Photos](https://support.apple.com/en-gb/guide/iphone/iphb08064d57/ios). It uses custom color matrices, not replicas of proprietary presets; near-duplicate warm/cool and monochrome variants are omitted. Previews are decoded to a maximum side of 1600 pixels, while export crops from the full-resolution source. Edited copies are lossless PNGs (the first frame for animated sources), saved to a temporary app-cache folder and imported into the existing account-scoped library. The original is never overwritten, and the temporary copy is removed after import or cancellation. Finishing without pixel edits preserves the original file format.

The login screen includes **자동 로그인**. When selected, the JWT and expiration are stored with Android's secure storage and verified against `/api/auth/me` at the next launch. Logging out, changing the server address, token expiration, or validation failure clears the saved session.

Static wallpaper application keeps a persistent app-private source copy before handing it to Android's `WallpaperManager`; Android keeps the applied wallpaper after the app exits and across device restarts. **라이브 배경화면 적용** downloads processed layers into app-private persistent storage before opening Android's required live-wallpaper confirmation screen. `WallpaperService` reloads that saved manifest and cached layers whenever Android recreates it, including after reboot.

Download and wallpaper actions refresh the project first because the S3 image links are short-lived. Android preserves the original extension and MIME type for the mobile image formats accepted by the backend, including HEIC/HEIF and AVIF.
